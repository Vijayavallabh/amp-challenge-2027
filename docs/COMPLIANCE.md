### Entry count

The two sources word this differently, so treat the stricter reading as binding:

- Kaggle competition rules: *"Each team may submit peptides generated by a given model only once…
  If a team has two or more sufficiently different models, it may submit one entry per model."*
- Website FAQ: *"Each research group may submit one primary entry. If you have meaningfully
  different methods you would like to compare, please **contact the organizers in advance**."*

So: one entry, and if a second model is wanted, contact the organizers **before** submitting.
There is no resubmission to correct a mistake, which is why `feat-008` (the organizers' validator,
run against the pushed public URL) is a hard gate on `feat-010`.

### Account identity — unresolved

The Kaggle API token on this machine (`~/.kaggle/kaggle.json`) belongs to **`prakashchhipa`**, not
to `j_v_v_07`. Consequences:

1. Entry status cannot be confirmed from here. Querying the competition as `prakashchhipa` returns
   `userHasEntered=False` and the data endpoint returns HTTP 403 — that reflects *that* account,
   and says nothing about `j_v_v_07`.
2. **Nothing may be submitted using this token.** Submitting through another person's account
   would breach the one-account rule and would attribute the entry to the wrong person.

To use the Kaggle CLI as the competing account, install that account's own token (Kaggle → Settings
→ API → Create New Token) at `~/.kaggle/kaggle.json`, or point `KAGGLE_CONFIG_DIR` at a directory
holding it. The token is a credential — don't commit it; `.gitignore` does not need to cover it
because it lives outside the repo.

## Peptide design constraints

Apply to both the 50,000-member library and the top 100.

| Constraint | Status | Where |
|---|---|---|
| 20 standard proteinogenic amino acids only (`ACDEFGHIKLMNPQRSTVWY`) | enforced | `constraints.is_valid_sequence`; generation filters, then re-checks |
| Length 8 to 50 residues | enforced | same |
| Linear peptides only | enforced by construction | plain sequence strings; nothing else is representable |
| No terminal modifications, including amidation | enforced by construction | no modification is ever emitted |
| No non-canonical residues, stapled, lipidated, glycosylated, PEGylated or dendrimeric constructs | enforced by construction | the alphabet restriction makes them unrepresentable |
| Unique sequences only | enforced | ordered de-duplication in `build_library`; re-checked in `check_library` |
| Library contains nothing identical to `data/antibacterial.fasta` | enforced | reference excluded during generation; `check_library` re-checks |
| Top 100 at or below 80% identity (Levenshtein ratio) to the reference set | enforced | `is_novel_enough`; rejects and replaces, then `check_top` re-checks |
